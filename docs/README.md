# Albion Roads Mapper — Documentation

A collaborative, real-time web application for *Albion Online* guild members to crowdsource and visualise temporary **Roads of Avalon** portal connections between zones. Users join a shared, password-protected room, report portal connections, and every participant's map updates live over WebSockets.

## Quick orientation

- **Monorepo** managed with pnpm workspaces. Four packages: `web/client` (Vue 3 SPA), `web/server` (Fastify API + WS), `web/shared` (domain types, Zod schemas, zone catalogue), `map-parser` (generator for the zone catalogue).
- **All writes flow through the server** (REST or WS operations); the server persists to Postgres and broadcasts the result to every authenticated socket in the room.
- **Zone data** is a committed JSON file (`web/shared/data/maps.json`, ~815 zones) generated by `map-parser` and adapted to runtime `Zone` objects by `web/shared/src/zones.ts`. Server and client never read the JSON directly — always via the `shared` package.
- **Auth** is per-room: bcrypt-hashed room passwords exchange for a JWT scoped to that room, used for both REST (`Authorization: Bearer`) and the WS handshake.

## Glossary

| Term | Meaning |
|---|---|
| **Roads of Avalon / roads** | Albion's shifting network of temporary zones connected by timed portals — the thing this app maps |
| **Zone** | A game map. Types: `roads`, `roadsHideout` (Avalonian Rest), `royalBlue/Yellow/Red`, `outlands`, `other` |
| **Connection** | A reported portal between two zones with an expiry time and slot size (7 or 20 players); may be `permanent` for static world links |
| **Room** | A shared map session, identified by a vanity slug, protected by a password + separate admin password |
| **Chain** | An independent connection tree within a room, rooted at a source zone. Every room has a primary chain rooted at the home zone; cross-chain connections are forbidden |
| **Handle** | A portal exit point on a zone's map shape (6 perimeter points + center); connections attach to specific handles |
| **Map shape** | The letter-coded outline of a roads zone (`c,f,h,o,p,s,t,x`, or `rest` for hideouts) determining handle layout and socket counts |
| **Room memory** | Per-room history of roads zones previously seen (features, handles, rotation, sighting timestamps) so re-adding a zone restores its layout |
| **Home zone** | The room's anchor zone (primary chain source), centred on the map |
